# راهنمای عملیات NeoContract

این راهنما برای اجرای محلی دمو و نگه‌داری داده آن است. فرمان‌ها را در ریشه پروژه و با Node.js 20 یا بالاتر اجرا کنید. احراز هویت و کنترل دسترسی در دامنه این نسخه نیست؛ سرور روی `127.0.0.1` گوش می‌دهد.

## تنظیم محیط

| متغیر | کاربرد |
| --- | --- |
| `PORT` | پورت برنامه؛ پیش‌فرض `4173` |
| `NEOCONTRACT_DATA_DIR` | پوشه داده PGlite؛ پیش‌فرض `.data/postgres`؛ مقدار `memory://` برای آزمون موقت |
| `NEOCONTRACT_DATABASE_URL` | اتصال PostgreSQL مستقل؛ در صورت تنظیم، بر پوشه PGlite اولویت دارد |
| `NEO_API_TOKEN` | توکن اتصال Neo غیرمحلی |
| `CHROME_PATH` | مسیر Chrome برای آزمون مرورگر |

متغیرها باید در محیط فرآیند تنظیم شوند؛ برنامه فایل `.env` را خودکار بارگذاری نمی‌کند. رشته اتصال و توکن واقعی را در مخزن یا فایل نمونه نگذارید. داده و پشتیبان‌های محلی داخل `.data` هستند و این پوشه در Git نادیده گرفته می‌شود.

## اجرای معمول و محیط آزمایشی جدا

```powershell
npm ci
npm start
```

برای محیط آزمایشی محلی، یک پنجره PowerShell جدا باز کنید. پوشه و پورت آن را از نسخه اصلی جدا نگه دارید:

```powershell
Set-Location 'E:\SJVS\Projects\NeoContract'
Remove-Item Env:NEOCONTRACT_DATABASE_URL -ErrorAction SilentlyContinue
$env:NEOCONTRACT_DATA_DIR = 'E:\SJVS\Projects\NeoContract\.data\staging-postgres'
$env:PORT = '4174'
npm start
```

محیط آزمایشی در [http://127.0.0.1:4174](http://127.0.0.1:4174) در دسترس است. بستن این پنجره، تنظیمات محیطی پنجره اصلی را تغییر نمی‌دهد. برای PostgreSQL مستقل، رشته اتصال پایگاه داده مخصوص همان محیط را در `NEOCONTRACT_DATABASE_URL` تنظیم کنید؛ حساب و اعتبارنامه آن جزو بسته پروژه نیست.

بررسی سلامت در `GET /api/health`، نوع موتور، پایداری، migrationها و شمار رکوردها را برمی‌گرداند.

## migration و داده اولیه

```powershell
npm run db:migrate
npm run db:seed
node scripts/database.mjs health
```

این فرمان‌ها از همان متغیرهای اتصال برنامه استفاده می‌کنند. شروع برنامه نیز migration و seed را اجرا می‌کند. migrationهای اجراشده با checksum ثبت می‌شوند؛ برای تغییر ساختار، migration جدید اضافه کنید. seed قابل تکرار است و داده اولیه، از جمله ۱۵ الگوی منتشرشده، مشتریان نمونه، مدیران حساب و کاتالوگ پایه را آماده می‌کند.

**در حالت PGlite، فقط یک فرآیند می‌تواند مالک پوشه داده باشد.** پیش از اجرای فرمان‌های مدیریت پایگاه داده، برنامه متصل به همان پوشه را با `Ctrl+C` متوقف کنید. محیط آزمایشی با پوشه مستقل می‌تواند جدا اجرا شود.

## پشتیبان‌گیری و بازیابی

ابتدا برنامه را متوقف کنید. برای پشتیبان‌گیری از PGlite، هیچ نمونه دیگری نباید همان پوشه داده را باز داشته باشد:

```powershell
npm run db:backup -- '.data/backups/contracts-before-update.json'
```

بدون آرگومان، فایل دارای زمان اجرا در `.data/backups` ساخته می‌شود. خروجی JSON شامل جدول‌های برنامه، زمان، نسخه ساختار و checksum است. فایل پشتیبان، اطلاعات قرارداد و مشتری دارد؛ نگه‌داری آن را مانند داده اصلی انجام دهید.

بازیابی را فقط در **پوشه جدید و خالی** انجام دهید. پیش از بازیابی، برنامه را روی پوشه مقصد اجرا نکنید؛ شروع عادی seed را وارد می‌کند و مقصد دیگر خالی نخواهد بود:

```powershell
Remove-Item Env:NEOCONTRACT_DATABASE_URL -ErrorAction SilentlyContinue
$env:NEOCONTRACT_DATA_DIR = 'E:\SJVS\Projects\NeoContract\.data\restored-postgres'
npm run db:restore -- '.data/backups/contracts-before-update.json'
node scripts/database.mjs health
$env:PORT = '4175'
npm start
```

پوشه نمونه بالا باید تازه باشد؛ اگر قبلاً استفاده شده، نام جدید انتخاب کنید. بازیابی checksum را کنترل می‌کند و پایگاه داده دارای داده موجود را بازنویسی نمی‌کند. پس از بررسی مشتریان، قراردادها، اسناد و اتصال‌های بازیابی‌شده، استفاده از این محیط را ادامه دهید. پوشه قبلی را تا پایان بررسی حفظ کنید. برای PostgreSQL مستقل نیز مقصد بازیابی باید پایگاه داده خالی و جدا باشد.

## واردات فناسا

در «تنظیمات و اتصال‌ها»، «دریافت از منبع رسمی» را انتخاب کنید. واردکننده کاتالوگ، قیمت‌گذاری، پشتیبانی و هر صفحه سرویس را می‌خواند؛ کاتالوگ فعلی ۸۷ سرویس دارد و برداشت آن ۹۰ صفحه است. مبدأ به HTTPS رسمی `fanasa.net` محدود است.

گزارش شامل URL، زمان، وضعیت HTTP، هش محتوا و هشدارهاست. دریافت ابتدا در وضعیت در انتظار بازبینی ثبت می‌شود. گزارش را بررسی و سپس «تأیید اپراتور» را انتخاب کنید تا کاتالوگ و نگاشت سرویس/SLA اعمال شوند. داده ناقص یا دریافت ناموفق، کاتالوگ فعال قبلی را حذف نمی‌کند.

برچسب برداشت رسمی با تأیید حقوقی تفاوت دارد. مبلغ اول سرویس، همیشه مبلغ نهایی قرارداد نیست: ردیف‌های پلن، مازاد، درصد، حداقل مبلغ، وابستگی سرویس و مالیات را در شرایط قرارداد در نظر بگیرید. متن و داده انتخاب‌شده هنگام ایجاد قرارداد ثابت ذخیره می‌شوند؛ واردات بعدی آن نسخه را تغییر نمی‌دهد.

## اتصال قرارداد به Neo

شناسه سازمان، فضای کاری، پروژه موجود و نشانی‌ها در `planning/neo-binding.json` قرار دارند. شناسه‌ها را با محیط مقصد تطبیق دهید؛ برای راه‌اندازی معمول نیازی به ساخت پروژه جدید یا اجرای bootstrap قدیمی نیست.

در اتصال محلی loopback، مسیر توسعه محلی Neo استفاده می‌شود. برای اتصال غیرمحلی HTTPS، `NEO_API_TOKEN` را در محیط برنامه تنظیم کنید. ابتدا از تنظیمات «بررسی اتصال Neo» را اجرا کنید؛ سپس در جزئیات قرارداد «اتصال / تلاش مجدد Neo» را بزنید.

برای قرارداد یک WorkItem مادر و برای مراحل فعال، کارهای فرزند و وابستگی مرحله‌ای ثبت می‌شود. کلیدها ثابت‌اند و نتیجه در پایگاه داده نگه‌داری می‌شود. در قطع پاسخ یا خطا، تلاش مجدد ابتدا رکوردهای موجود را پیدا می‌کند. رکورد متعلق به عامل/گفت‌وگوی دیگر تصاحب نمی‌شود. این اتصال، اجرای خودکار همه کارها یا استقرار تولیدی را اعلام نمی‌کند.

## آزمون و رفع اشکال

```powershell
Remove-Item Env:NEOCONTRACT_DATABASE_URL -ErrorAction SilentlyContinue
npm test
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:e2e
```

آزمون E2E به پورت آزاد ۴۱۸۸ و Chrome نیاز دارد و سرور آزمایشی خودش را اجرا می‌کند. در خطا، فایل‌های Playwright در `test-results` قرار می‌گیرند. دستور `npm test` آزمون‌های منطق، پایگاه داده، API و اتصال‌های شبیه‌سازی‌شده را اجرا می‌کند؛ نتیجه آزمون را از خروجی همان اجرا بخوانید.

| نشانه | بررسی |
| --- | --- |
| پورت در حال استفاده است | مقدار `PORT` را تغییر دهید؛ برای E2E پورت ۴۱۸۸ را آزاد کنید |
| PGlite باز نمی‌شود | فرآیند دیگری را که همان پوشه داده را باز کرده متوقف کنید |
| داده مورد انتظار دیده نمی‌شود | `NEOCONTRACT_DATABASE_URL` و `NEOCONTRACT_DATA_DIR` همان پنجره را بررسی کنید |
| دریافت فناسا شکست خورد | گزارش واردات و دسترسی شبکه به دامنه رسمی را بررسی و دوباره دریافت کنید |
| اتصال Neo در دسترس نیست | نشانی‌ها، شناسه پروژه، سرویس محلی یا توکن محیط را بررسی کنید |
| checksum پشتیبان معتبر نیست | از فایل اصلی سالم استفاده کنید؛ فایل پشتیبان را دستی ویرایش نکنید |
