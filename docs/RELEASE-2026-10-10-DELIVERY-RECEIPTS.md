# پذیرش رسید اتصال قرارداد به مرکز

## دامنه

PCC نسخه ۰٫۴ پذیرش اولیه HTTP 202 را از مشاهده واقعی Gateway HTTP 200 جدا
می‌کند. NeoContract اکنون این دو مرحله و پاسخ superseded را مستقل ذخیره و نمایش
می‌دهد. receipt تنها فیلدهای مجاز دارد؛ state کامل مرکز به مرورگر داده نمی‌شود.
شکست retry پذیرش قبلی را پاک نمی‌کند و نسخه superseded خودکار دوباره ارسال نمی‌شود.

migration ۱۲، محتوای نرمال‌شده ارسال، digest و مرجع نگاشت را در همان outbox ثابت
می‌کند. snapshot پیش از تماس شبکه ثبت می‌شود؛ تغییر نگاشت هنگام retry پیش از
ارسال رد می‌شود. SQL از تغییر snapshot و receipt تأییدشده نیز جلوگیری می‌کند.
رویداد جدید، grant، UUID، درصد، wallet یا observer فرضی ایجاد نشده است.

## آزمون‌های محلی

[مبنای خوانده‌شده مالک رسید](../planning/service-limit-receipt-source.json)
مسیر و hash دو فایل واقعی PCC را ثبت می‌کند؛ تست‌های این مخزن، receiver مرکزی
را اجرا نمی‌کنند و مبنای خوانده‌شده شاهد انتشار مرکزی نیست.

- ۹ آزمون واحد/پایگاه/backup موفق، صفر شکست: migration، دوام، قیدهای SQL،
  اصلاحیه، idempotency، snapshot ثابت، تغییر نگاشت، پذیرش ۲۰۲، شکست retry و
  حفظ receipt، ACK واقعی با tuple/hash/زمان، superseded و منع retry.
- intake پاسخ از لحاظ اندازه بایت UTF-8، UTF-8 نامعتبر، JSON خراب و cancel
  stream بررسی شد؛ سقف پاسخ ۶۴ KiB است.
- ۵ سناریوی مرورگر موفق: گردش ظرفیت در ۱۴۴۰/۳۹۰، نقش مشاهده‌گر و نمایش شواهد
  پذیرش/superseded در ۱۴۴۰/۳۹۰. سناریوی شواهد، mock صریح UI است؛ observation
  واقعی در پایگاه تولید ثبت نمی‌کند.

## مرز عملیاتی

observer مرکز هنوز پیش‌فرض unavailable است و فعال‌سازی dispatcher به گیت چرخه
pause/resume/close، binding مصوب، producer معتبر و پذیرش عملیاتی وابسته است.
این تغییر، receiver مرکزی یا APISIX/Redis زنده را نصب یا فعال نمی‌کند. پنج پیشنهاد
واقعی برای آزمون امضاشده یا دارای TPS فرضی نمی‌شوند.

## انتشار اتصال و پذیرش زنده

نسخه `40534576c336209026327ba50e1f3b8ac00a5664` با هر دو job موفق
[CI](https://github.com/SeyediDev/NeoContract/actions/runs/38073806449) منتشر شد.
PostgreSQL موقت سرور با migration ۱۲، snapshot ثابت، پذیرش مستقل و superseded
موفق بود. سرویس healthy، صفر restart، تطابق ۱۱ فایل اجرایی تغییرکرده و حفظ
اثر انگشت داده‌های ۵۳ جدول تأیید شد. پشتیبان تازه:
`/opt/neocontract-backups/delivery-20261010t175134z.dump`؛ image بازگشت
`neocontract-app:before-delivery-20261010t175134z`.

سه سناریوی زنده SSO، مدیر ۱۴۴۰/۳۹۰ و مشاهده‌گر ۳۹۰، موفق شدند: چهار تننت، پنج
پیشنهاد، migration ۱۲، پنل مشتری/اقتصاد/ارائه‌دهنده و وضعیت ظرفیت بدون نسخه
یا receipt ساختگی. هیچ درخواست تغییر تجاری ثبت نشد و TLS با CA معتبر محلی بود.

## ادامه UI با اولویت کاربر

مسیر چهارمرحله‌ای از مدرک امضا تا مشاهده مقصد به رابط شواهد اضافه شد.
`/delivery-preview.html` پیش‌نمایش تعاملی مستقل چهار وضعیت است؛ نشان داده نمایشی
دارد، هیچ API فراخوانی نمی‌کند و آمار نمونه به سند یا مجوز واقعی تبدیل نمی‌شود.
نشان‌های رسمی فن‌آسا و رایان، tokens موجود، RTL، موبایل و صفحه‌کلید استفاده می‌شوند.
چهار آزمون قواعد رسید/مراحل و هفت سناریوی مرورگر موفق بودند؛ پیش‌نمایش در
دسکتاپ ۱۴۴۰ و موبایل ۳۹۰ بازبینی بصری شد. اندازه نشان رایان در موبایل برای خوانایی
اصلاح شد؛ پیش‌نمایش هیچ درخواست API نداشت.

اجرای CI مستندات قبلی `38068501554` در یک GET آزمون اجرای قرارداد پس از دانلود
به ECONNRESET رسید؛ ۷۷ سناریوی دیگر موفق بودند. همان GET بدون اثر تجاری، یک بار
فقط برای خطای transport دوباره خوانده می‌شود. assertionها، timeout و فرمان‌های
تغییردهنده برای پوشاندن خطا تغییر نکرده‌اند.
