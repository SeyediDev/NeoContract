# پنل مشتری و پایش فراخوانی

نشانی: `https://contracts.fanasa.net.local/#view=client`، با همان SSO و مرز
تننت NeoContract. پنل ارائه‌دهنده در `#view=providers` است. هر درخواست GET
عضویت فعال و تننت مجاز را بررسی می‌کند؛ مشاهده‌گر امکان تغییر شرایط ندارد.

## قابلیت‌ها

- بازه پیش‌فرض ۲۴ ساعت و حداکثر ۳۱ روز؛ فیلتر سرویس، status code و جست‌وجو.
- جست‌وجوی واژه یا عبارت در بدنه JSON پاک‌سازی‌شده ورودی/خروجی، مسیر و شناسه
  درخواست با `websearch_to_tsquery('simple',...)` و شاخص GIN؛ جست‌وجوی زیررشته
  دلخواه یا جست‌وجو در داده‌های حذف‌شده نیست.
- صفحه‌بندی keyset با ترتیب زمان/شناسه؛ حداکثر ۱۰۰ سطر، بدون OFFSET یا count
  کامل برای هر صفحه. نشان صفحه به فیلتر و بازه ثابت گزارش متصل است.
- تعداد، نرخ خطای ۴xx/۵xx، میانگین latency، کران بالای P95، حجم ورودی/خروجی،
  روند ساعتی خطا/فراخوانی/۴۲۹، وضعیت پاسخ‌ها و جزئیات ورودی/خروجی.
- نمودار SVG سبک با جدول قابل دسترس، RTL و موبایل. P95 از سطل‌های latency
  به دست می‌آید و صدک دقیق خام نیست.
- تجمیع SQL از rollup ساعتی با اصلاح دقیق دو ساعت مرزی؛ جست‌وجوی محتوا بر
  evidence شاخص‌دار همان بازه. پاسخ گزارش به ابعاد تجمیع‌شده محدود است؛ حداکثر
  ۱۰۰ سرویس برتر. مهلت query گزارش پنج ثانیه است.

## دریافت داده واقعی

`POST /api/telemetry/ingest` پیش‌فرض غیرفعال است. فعال‌سازی فقط پس از ثبت و
پذیرش producer واقعی Gateway/backend، نگاشت تننت و بررسی پاک‌سازی بدنه‌ها:

```text
NEOCONTRACT_TELEMETRY_ENABLED=true
NEOCONTRACT_TELEMETRY_PRODUCERS=<private JSON producer bindings>
NEOCONTRACT_TELEMETRY_RETENTION_DAYS=30
```

هدر Bearer مستقل producer و `X-Tenant-Id` لازم‌اند؛ اعتبار SSO، cookie یا توکن
تننت مرورگر اجازه ingest نمی‌دهد. producer فقط برای UUIDهای صریح خودش مجاز
است. سقف ۱۰۰ رویداد در batch و ۱ MiB در درخواست؛ بدنه پاک‌سازی‌شده هر سمت
حداکثر ۶۴ KiB؛ رویداد خارج retention یا بیش از یک دقیقه در آینده رد می‌شود.

کلیدهای شناخته‌شده رمز، token، cookie، api key و اطلاعات حساس پوشانده می‌شوند؛
رشته Bearer، JWT و email هم پوشانده می‌شوند. مسیر query/fragment نمی‌پذیرد.
این قواعد جای پاک‌سازی upstream محتوای آزاد و اطلاعات حساس اختصاصی سرویس را
نمی‌گیرند؛ producer باید محتوای قابل انتشار را طبق قرارداد capture محدود کند.
شناسه رویداد پایدار، retry را بدون شمارش دوباره می‌پذیرد؛ تغییر همان رویداد
تعارض است. ثبت raw و rollup در یک تراکنش انجام می‌شود.

## نگه‌داری

retention یک تا ۹۰ روز، پیش‌فرض ۳۰. پس از فعال‌سازی producer، job زیر را
ساعتی در محیط سرور با همان اتصال پایگاه اجرا کنید؛ بدون `--apply` فقط شمارش
کاندیدای حذف چاپ می‌شود. log بدنه یا credential تولید نمی‌کند.

```bash
node scripts/customer-telemetry.mjs prune --apply
```

ساعت مرزی rollup از raw باقی‌مانده بازسازی می‌شود. قواعد retention پایگاه،
پشتیبان‌های عملیاتی را حذف نمی‌کند؛ سیاست نگه‌داری backup مستقل است.

## عرضه مرکزی و حسابداری

پنل مشتری یک ورودی سرویس از محصول NeoContract در مرکز تأییدشده رایان است؛
ثبت دیگری برای tenant/product/offer داخل این برنامه ایجاد نمی‌شود.
[بسته درخواست ثبت](../planning/customer-portal-service.json) کلید سرویس و URL
را ثبت می‌کند، اما رسید رجیستری مرکزی نیست. مالک باید از ثبت واقعی neocontract
گرفته شود؛ قیمت عرضه از قرارداد یا تعرفه مصوب وارد شود. نرخ فرضی اضافه نشده است.

در VPS فعلی رجیستری و Accounting مرکزی مستقر نیستند؛ عرضه در سبد مرکزی و
دسترسی پنل توسعه‌دهنده هنوز نیازمند ثبت و پذیرش آن سرویس‌هاست. داده پایش
**مصرف قابل صورتحساب، ledger یا موجودی کیف پول نیست**. همه پاسخ‌ها
`financialUsage:false` دارند؛ هیچ عدد موجودی فرضی در داشبورد نمایش داده نمی‌شود.
