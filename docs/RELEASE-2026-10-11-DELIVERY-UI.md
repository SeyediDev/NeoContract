# پذیرش رابط مسیر اتصال قرارداد — ۱۱ اکتبر ۲۰۲۶

## رابط و پیش‌نمایش

مسیر چهارمرحله‌ای «مدرک امضا، ثبت تغییر، پذیرش مرکز، مشاهده مقصد» به شواهد
ظرفیت قرارداد اضافه شد. تأیید مقصد تنها با receipt acknowledged نمایش داده
می‌شود؛ پذیرش اولیه، توقف/جایگزینی نسخه و آخرین خطای ارسال جدا دیده می‌شوند.

[پیش‌نمایش تعاملی](https://contracts.fanasa.net.local/delivery-preview.html)
چهار وضعیت را با داده صریحاً نمایشی نشان می‌دهد. دکمه‌ها فقط حالت رابط را تغییر
می‌دهند؛ API، قرارداد، مجوز، دفتر مالی یا کیف پول واقعی را تغییر نمی‌دهند.
نشان‌های رسمی فن‌آسا و رایان، قلم محلی، tokens موجود، RTL، صفحه‌کلید و چیدمان
دسکتاپ/موبایل استفاده شدند. اندازه نشان رایان در موبایل برای خوانایی اصلاح شد.

## شواهد آزمون

- چهار آزمون قواعد receipt/مسیر موفق؛ هفت سناریوی مرورگر شامل گردش ظرفیت،
  مشاهده‌گر، رسیدهای pending/superseded و تعامل پیش‌نمایش در ۱۴۴۰/۳۹۰ موفق.
- پس از اصلاح اندازه نشان، رندر مستقل نهایی در هر دو عرض موفق؛ هیچ API فراخوانی
  نشد، overflow یا خطای JavaScript دیده نشد. تصاویر نهایی بازبینی شدند.
- هر دو job [CI نسخه دقیق](https://github.com/SeyediDev/NeoContract/actions/runs/38113967836)
  برای `d633254a8388c960e152e6872d3939d49c955dce` موفق شدند.
- پذیرش زنده پس از انتشار: مدیر قرارداد ۱۴۴۰/۳۹۰ و مشاهده‌گر ۳۹۰، ورود SSO،
  هر چهار سناریو، صفحه‌کلید و نبود overflow موفق. پنل نمایشی هیچ API فراخوانی
  نکرد؛ هیچ درخواست تغییر تجاری ثبت نشد. TLS با CA داخلی معتبر بررسی شد.
