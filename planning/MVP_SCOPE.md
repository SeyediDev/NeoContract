# دامنه MVP نئوکنتراکت

تاریخ: ۲۰۲۶-۰۹-۳۰ — مبنای برنامه اجرایی CTR-001. این سند تعریف محصول است؛ قابلیت‌های کامل‌شده در work-items.json مشخص‌اند.

## هدف و محدوده

دموی وب فارسی RTL برای سازمان مرکزی یک هلدینگ، با پنل مدیریت قرارداد، کاتالوگ فن‌آسا، مشتریان هلدینگی و اکانت‌منیجرها. کاربران و کنترل دسترسی محصول در این مرحله خارج از محدوده‌اند. مدل SaaS باید مالکیت داده هر tenant را حفظ کند؛ credential اتصال Neo مستقل از مدیریت کاربران این محصول است.

## موجودیت‌ها

Tenant ← هلدینگ/واحد مالک؛ مشتری ← هلدینگ یا شرکت تابع؛ مدیر حساب ← مسئول تجاری مشتری. منبع کاتالوگ ← پهنه ← مرکز قابلیت ← سرویس. الگو ← نسخه منتشرشده شامل متن، متغیرها و مراحل. قرارداد شامل طرفین، سرویس‌ها، مدل درآمد، SLA، سند و فرآیند مستقل است.

## جریان قرارداد

انتخاب مشتری و سرویس‌ها → انتخاب نسخه الگو و مدل درآمد → اطلاعات قرارداد → تعیین SLA سرویس‌ها → سفارشی‌سازی مراحل و نقش‌ها → بازبینی → ایجاد پیش‌نویس. جریان بعدی draft → in_process → awaiting_signature → active است؛ expired، terminated و cancelled وضعیت‌های پایانی تجاری هستند.

هر قرارداد هنگام ایجاد، نسخه ثابت متن الگو، متغیرها، مشخصات مشتری/مدیر حساب، سرویس‌ها، شرایط مالی، SLA و مراحل خود را نگه می‌دارد. تغییر الگو یا کاتالوگ نباید قرارداد قبلی را تغییر دهد. اصلاح قرارداد فعال باید با الحاقیه نسخه‌دار انجام شود.

## نقش‌ها و قواعد فرآیند

نقش‌های فرآیند: درخواست‌کننده، مدیر حساب، مسئول سرویس، حقوقی، مالی، مدیریت و امضاکننده. این‌ها مسئولیت تجاری مرحله‌اند و حساب کاربری یا RBAC ایجاد نمی‌کنند. پیش‌فرض: تنظیم درخواست → بررسی سرویس/SLA → بررسی حقوقی → بررسی مالی → تأیید مدیریت → امضا → فعال‌سازی. نقش، مهلت، ترتیب و مراحل اختیاری برای هر قرارداد قابل تنظیم است؛ امضا و تأییدهای الزامی حذف نمی‌شوند.

SLA سرویس (دسترس‌پذیری، پاسخ، رفع، تقویم پشتیبانی) با مهلت انجام مرحله قرارداد دو مفهوم مستقل است. روز کاری نباید بدون تقویم به دقیقه تقویمی تبدیل شود.

## قواعد منبع و الگوها

منبع دقیق https://fanasa.net/fa و صفحات رسمی products، pricing و pricing/support است. داده موجود مشاهده مرورگر با وضعیت browser-observed-unverified است. مجموع tierها دلیل نگاشت SLA هر سرویس نیست؛ SLA، روش تحویل و قیمت نامشخص باید صریحاً نامشخص بماند یا توسط کاربر با provenance مستقل انتخاب شود.

مدل‌های مورد نیاز برای CTR-017: قرارداد مادر هلدینگ با سفارش خدمت، اشتراک per-user، مصرفی، مبلغ ثابت، ترکیبی، پروژه‌ای/خروجی‌محور و پیوست پشتیبانی/SLA. شرایط اختصاصی این الگوها باید از سرویس منتخب و مدل درآمد تأییدشده ساخته شود؛ متن حقوقی نهایی نیازمند پذیرش نقش حقوقی در همان فرآیند است.

## مرز نسخه حاضر و پذیرش نهایی

نسخه حاضر سرور static و داده در حافظه صفحه دارد. فایل‌های PostgreSQL طراحی و seed هستند؛ اتصال SQL اجرا نشده است. استفاده از Neon الزامی نیست و با زیرساخت Neo یکسان نیست. پذیرش دمو پس از ذخیره و بازیابی واقعی قرارداد، فرآیند سفارشی، snapshot مستقل، نگاشت درست CRM و تست RTL/موبایل انجام می‌شود.

ثبت پروژه/تسک‌ها و اتصال مراحل به Neo، همگام‌سازی تولیدی منبع، استقرار staging و migration هر یک کار مستقل دارند؛ فایل برنامه به معنی انجام اتصال‌ها نیست.
