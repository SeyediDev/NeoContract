## اجرای فعلی

CTR-011 (ثبت مشاهده منبع)، CTR-001 (تعریف دامنه) و CTR-003 (زیرساخت اجرای دمو) با شواهد تکمیل شده‌اند. کار آماده بعدی CTR-002 است. وجود UI یا فایل SQL به معنی تکمیل قابلیت یا اجرای دیتابیس نیست.

CTR-016 از قبل برای الگوهای غیرخرید ثبت شده بود و حفظ شد. CTR-017 برای مدیریت نسخه الگو و CTR-018 برای API و ذخیره‌سازی به برد افزوده شدند. عنوان‌های قدیمی شامل Neon صرفاً حفظ سابقه‌اند؛ الزام میزبانی Neon وجود ندارد و Neo زیرساخت جداگانه‌ای است.

## معیارها و شواهد

### CTR-011 — ثبت کاتالوگ مشاهده‌شده فن‌آسا و محدودیت‌های منبع

داده مشاهده‌شده موجود است؛ تأیید تولیدی و نگاشت SLA هر سرویس در CTR-015 انجام می‌شود.

- ثبت URL، تاریخ، روش مشاهده و وضعیت browser-observed-unverified
- وجود ۵ پهنه، ۱۴ مرکز و ۸۷ کد یکتا و نگاشت مدل درآمدی
- تفکیک مجموع SLAها از نگاشت ناموجود SLA و روش تحویل هر سرویس

فایل‌های مرتبط: [planning/fanasa-catalog-observed.json](../planning/fanasa-catalog-observed.json)، [planning/fanasa-source-research.md](../planning/fanasa-source-research.md)

### CTR-001 — تثبیت دامنه MVP و قواعد تولید قرارداد

دامنه در planning/MVP_SCOPE.md ثبت شده است؛ این پذیرش مربوط به تعریف دامنه است، نه پیاده‌سازی همه آن.

- دامنه، نقش‌های فرآیند، مرز tenant و چرخه قرارداد مستند باشد
- SLA سرویس از زمان انجام مرحله فرآیند جدا باشد
- دامنه دمو، محدودیت‌ها و کارهای خارج از MVP روشن باشد

فایل‌های مرتبط: [planning/MVP_SCOPE.md](../planning/MVP_SCOPE.md)

### CTR-003 — تکمیل زیرساخت اجرای دمو و تست HTTP

سرور اصلاح شد؛ ۸ تست HTTP موفق، بدون شکست یا skip. API و ذخیره‌سازی در CTR-018 است.

- اجرای Node روی loopback و ارائه صحیح HTML، JS، CSS و JSON
- HEAD و پاسخ‌های 400، 403، 404، 405 صحیح؛ URI خراب سرور را متوقف نکند
- عبور از مسیر public و symlink بیرونی مسدود و تست HTTP روی پورت موقت موفق باشد

فایل‌های مرتبط: [server.mjs](../server.mjs)، [tests/server.test.mjs](../tests/server.test.mjs)، [planning/EXECUTION_LOG.md](../planning/EXECUTION_LOG.md)

### CTR-002 — اصلاح و بازبینی طراحی SQL و جداسازی tenantها

DDL موجود است؛ نگاشت فرضی SLA، تقویم کاری و integrity tenant نیاز به اصلاح دارد. اجرای واقعی DB هنوز انجام نشده.

- روابط tenant و مراجع الگو/مشتری/قرارداد از ارجاع بین tenantها جلوگیری کند
- SLA نامشخص سرویس به‌جای T2 فرضی ثبت شود؛ روز کاری واحد مستقل داشته باشد
- نسخه الگو، فرآیند و شرایط سرویس در قرارداد قابل snapshot باشد

فایل‌های مرتبط: [database/schema.sql](../database/schema.sql)، [database/fanasa-catalog.sql](../database/fanasa-catalog.sql)

### CTR-008 — اجرای آزمایشی SQL و seed قابل تکرار

فایل seed موجود است؛ اجرای SQL و نتیجه آزمون ثبت نشده است.

- تکرار seed رکورد تکراری نسازد و شمارش ۵/۱۴/۸۷ تأیید شود
